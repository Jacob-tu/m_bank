# Skill: design-review - 设计评审

## 触发方式

```
/design-review <设计文档路径或模块名>
```

## 执行步骤

### Step 1: 读取设计文档

根据输入路径或模块名，读取相关设计文档：
- `mbank-docs/design/architecture.md` - 架构设计
- `mbank-docs/design/data-model.md` - 数据模型
- `mbank-docs/api/api-spec.md` - API 接口规范
- `mbank-docs/design/interaction-flow.md` - 交互流程

同时读取对标规范：
- `.qoder/rules/coding-standard.md`
- `.qoder/rules/api-design.md`
- `.qoder/rules/security-policy.md`
- `.qoder/rules/testing-standard.md`

### Step 2: 确定评审维度

根据设计文档内容自动选择适用的评审维度：

| 维度 | 适用条件 | 关注点 |
|------|----------|--------|
| 架构设计 | 存在架构图或分层描述 | 分层合理性、模块职责、技术选型、扩展性 |
| 数据模型 | 存在表结构或 ER 图 | 字段类型、索引、约束、状态机、范式 |
| API 设计 | 存在接口定义 | RESTful 规范、状态码、请求/响应格式、错误码 |
| 安全设计 | 存在认证/加密/审计描述 | 认证方案、密码安全、鉴权规则、审计覆盖 |
| 交互流程 | 存在时序图或流程图 | 完整性、异常覆盖、事务边界 |

### Step 3: 逐维度评审

对每个适用维度，按以下格式评审：

1. 列出该维度的检查项
2. 逐项评估：**PASS** / **ISSUE** / **SUGGESTION** / **INFO**
3. 对非 PASS 项给出具体问题描述和改进建议

#### 问题严重级别定义

| 级别 | 含义 | 处理方式 |
|------|------|----------|
| MAJOR | 安全漏洞、数据一致性风险、违反强制规范 | 必须修复，阻塞代码生成 |
| MINOR | 字段遗漏、命名不规范、不一致 | 建议修复，不阻塞 |
| SUGGESTION | 扩展性、性能优化、最佳实践 | 可选改进 |
| INFO | 技术债务记录、后续注意事项 | 仅记录 |

### Step 4: 跨维度一致性检查

检查设计文档之间的一致性：
- 数据模型字段是否支撑所有 API 的请求/响应
- 时序图中的方法调用是否与架构分层一致
- 安全设计中的规则是否在 API 和流程中落实
- 状态机定义在各文档中是否统一

### Step 5: 生成评审结论

评估整体设计质量并给出结论：

- **通过**：无 MAJOR/MINOR 问题
- **有条件通过**：有 MINOR 问题但不阻塞，或有 MAJOR 问题但可在代码生成时修复
- **不通过**：有 MAJOR 问题需先修改设计文档

### Step 6: 输出评审记录

输出结构化评审记录到 `mbank-docs/review/` 目录。

## 评审规则

### 架构设计检查清单
- 分层是否清晰（Controller → Service → Repository → Entity）
- 模块职责是否单一
- 依赖方向是否正确（上层依赖下层，无循环）
- 接口隔离（Service 定义接口 + Impl 实现）
- 技术选型是否有合理理由
- 扩展性（新模块接入是否影响现有结构）

### 数据模型检查清单
- 主键策略是否合理
- 字段类型是否匹配业务语义（金额用 DECIMAL、状态用 VARCHAR）
- 必要索引是否设计（查询条件、唯一约束）
- 外键约束是否明确
- 状态机定义是否完整且与需求一致
- 并发控制机制是否预留（乐观锁 version 字段）

### API 设计检查清单
- URL 是否遵循 RESTful 规范
- HTTP Method 语义是否正确
- 请求/响应格式是否统一
- HTTP 状态码使用是否恰当
- 错误响应是否覆盖所有业务场景
- 认证/鉴权标注是否完整

### 安全设计检查清单
- 认证算法和密钥长度是否达标
- 密码存储是否使用强哈希（BCrypt/Argon2）
- Token 载荷是否最小化（无敏感数据）
- Token 失效机制是否完备
- 鉴权规则是否覆盖所有接口
- 审计日志是否覆盖关键操作
- 敏感数据是否脱敏

### 交互流程检查清单
- Happy Path 是否完整
- 异常分支是否覆盖
- 事务边界是否明确
- 参与者标注是否清晰
- 是否存在重复操作可优化
