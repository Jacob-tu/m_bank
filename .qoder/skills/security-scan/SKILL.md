# Skill: security-scan - 代码安全扫描

## 触发方式

```
/security-scan <目标路径或文件>
```

## 执行步骤

### Step 1: SQL 注入扫描

扫描所有数据库查询代码：
- 检查是否使用参数化查询
- 检查是否有字符串拼接 SQL
- 检查 @Query 注解是否安全
- 检查原生查询是否参数化

### Step 2: XSS 扫描

扫描前端和后端代码：
- 前端：检查 v-html 使用、用户输入渲染
- 后端：检查输入校验、输出编码

### Step 3: 认证鉴权扫描

扫描安全配置：
- JWT 密钥强度
- Token 过期策略
- 刷新 Token 机制
- 密码加密算法
- HTTPS 配置

### Step 4: 敏感数据扫描

扫描数据处理：
- 密码是否加密存储
- 手机号是否脱敏展示
- 银行卡号是否脱敏
- 日志是否打印敏感信息
- 响应是否泄露内部信息

### Step 5: CORS 和 CSP 扫描

检查跨域和内容安全策略：
- CORS 允许的来源
- CSP 头配置
- Cookie 安全属性

### Step 6: 业务安全扫描

检查金融业务特有风险：
- 转账金额校验完整性
- 并发转账幂等性
- 越权访问防护
- 事务完整性
- 审计日志完整性

### Step 7: 生成安全报告

输出安全扫描报告：
- 问题列表（等级、文件、行号、描述、修复建议）
- 安全评分
- 修复优先级建议

## 问题等级

| 等级 | 含义 | 示例 |
|------|------|------|
| CRITICAL | 必须立即修复 | SQL 注入、密码明文存储 |
| HIGH | 必须在发布前修复 | JWT 弱密钥、缺失认证 |
| MEDIUM | 建议修复 | CORS 配置过宽、缺失审计日志 |
| LOW | 改进建议 | 日志级别过高、缺失输入校验 |

## 输出

安全扫描报告以代码审查报告格式输出，包含：
- 问题汇总表
- 详细问题及修复代码
- 安全评分和改进建议
